Date: 2026-09-19. Scope: local source, build configuration, installed macOS package, isolated browser UI, and mocked functional tests.

Tests and this report were added; earlier tracking/payment changes remain in the working copy.

## Prioritized Findings

P0 means urgent containment. P1 means fix before release. P2 means important correctness/reliability work. Evidence is marked **reproduced**, **UI observed**, **source confirmed**, or **conditional**. Source-confirmed issues have not necessarily been exercised against live services.

### 1. P0: Payment secrets are distributed with the client

**Source/package confirmed.** [package.json:156](/Users/kalpa/Documents/Mediscribe/package.json:156) explicitly copies `.env` into platform resources despite excluding it from the main file list. [main.js:4145](/Users/kalpa/Documents/Mediscribe/electron/main.js:4145) also contains a hardcoded payment-secret fallback. The installed package contains an `.env` resource. Secret values are intentionally omitted from this report; their current validity was not tested. A desktop package cannot protect merchant-side credentials from its recipient. Remove these credentials from client code/resources, rotate any exposed active secrets, and move payment/admin operations to an authenticated backend. Removing a public source line alone does not revoke the old secret or remove released copies.

### 2. P1: Transcription cleanup changes clinically meaningful text

**Reproduced.** [main.js:6525](/Users/kalpa/Documents/Mediscribe/electron/main.js:6525) changes `.5 mg` into `5 mg` and `Arm (left) pain.` into `Arm pain.` It strips leading punctuation and all bracketed/parenthesized text. This is a release-blocking accuracy defect. Preserve numbers, signs, units, laterality, and qualifiers; filter only explicit non-speech markers. Add preservation tests and retain the original transcript for comparison. This finding concerns text transformation, not a clinical assessment.

### 3. P1: Captured payment amount is not checked against the plan

**Reproduced with a mocked gateway response.** [main.js:4039](/Users/kalpa/Documents/Mediscribe/electron/main.js:4039) trusts plan notes and copies the captured amount without checking canonical price/currency. A mocked captured USD 0.01 payment with yearly notes granted a yearly license. This does not establish that the gateway would accept that live checkout amount; it proves the verifier lacks the required check. Create orders server-side, bind them to authenticated purchaser/plan/device, and verify order, currency, discounts, amount, capture and refund state before fulfillment. Do not trust client-written notes as pricing authority.

### 4. P1: Admin IPC trusts caller-supplied identity

**Reproduced mutation; source-confirmed read bypass.** [main.js:4133](/Users/kalpa/Documents/Mediscribe/electron/main.js:4133) skips the allowlist check when the email argument is absent and otherwise trusts a supplied email. [main.js:4785](/Users/kalpa/Documents/Mediscribe/electron/main.js:4785) changes subscriber entitlement without authenticating the caller. The reproduction uses a stubbed admin SDK, not real customer data. Exploitation requires reachable IPC and usable runtime credentials. Put authorization on a backend using verified identity/roles. Do not fix packaging failures by shipping Firebase service-account keys to customers.

### 5. P1: Offline entitlement signing accepts unverified claims

**Reproduced.** [main.js:3746](/Users/kalpa/Documents/Mediscribe/electron/main.js:3746) signs a renderer-supplied record containing `isActivated: true` and an arbitrary future expiry. Signing caller data does not prove a purchase. Use a server-issued entitlement signature, with only its verification public key in the client; validate identity, expiry, version, and a bounded offline policy.

### 6. P1: Renderer has overly broad native file privileges

**Source confirmed; no exploit run.** [main.js:2554](/Users/kalpa/Documents/Mediscribe/electron/main.js:2554) disables web security. The preload-accessible handlers at [main.js:5351](/Users/kalpa/Documents/Mediscribe/electron/main.js:5351) and [main.js:5484](/Users/kalpa/Documents/Mediscribe/electron/main.js:5484) accept arbitrary file paths for deletion/writing. A compromised renderer could abuse those privileges within OS permissions. Restore web security, constrain file operations to app-owned paths or explicit user-selected handles, validate IPC sender/frame, and isolate external payment content from privileged application code.

### 7. P1: Transcripts are written into persistent diagnostic logs

**Source confirmed.** [main.js:6752](/Users/kalpa/Documents/Mediscribe/electron/main.js:6752) logs raw text, and subsequent pipeline logging writes cleaned/corrected text into `debug_log.txt` without an explicit diagnostic consent or retention boundary in this path. Medical dictation can contain sensitive information. Default to content-free diagnostics; make any content logging opt-in, short-lived, redacted, and visible. Do not upload existing logs without review.

### 8. P1: Fallback authentication stores plaintext passwords

**Source confirmed.** [main.js:3641](/Users/kalpa/Documents/Mediscribe/electron/main.js:3641) stores supplied passwords directly in `local_simulated_users.json`. Production-reachable simulated/reviewer login paths also exist. Disable simulated identity in production, use provider-backed authentication, and migrate/remove plaintext storage safely. An offline session should be a protected, bounded token, not a stored password. Reviewer access should be deliberately scoped, not treated as ordinary verified identity.

### 9. P1: Successful payment recovery can leave the account locked

**Source confirmed.** Manual recovery at [pricing-view.tsx:88](/Users/kalpa/Documents/Mediscribe/src/components/pricing-view.tsx:88) writes a local license and reloads without updating the Firestore entitlement used by [mediscribe-app.tsx:207](/Users/kalpa/Documents/Mediscribe/src/components/mediscribe-app.tsx:207). Automatic checkout also catches entitlement-write errors but still displays success at [pricing-view.tsx:299](/Users/kalpa/Documents/Mediscribe/src/components/pricing-view.tsx:299). Use one durable, idempotent backend fulfillment operation for checkout, webhooks, and manual recovery. Distinguish payment received from access granted and provide a retryable reconciliation state.

### 10. P1: Web/Android checkout has no implemented activation path

**Source confirmed.** [pricing-view.tsx:286](/Users/kalpa/Documents/Mediscribe/src/components/pricing-view.tsx:286) relies on optional Electron IPC after checkout. In a normal browser or Capacitor app that bridge is absent, so the successful-payment callback cannot grant access. Implement shared backend verification/fulfillment and call it from all supported platforms. Until tested, disable purchases on unsupported clients rather than accept payment without delivery.

### 11. P1: OAuth callback lacks state validation and mishandles errors

**Source confirmed.** [oauth-handler.js:133](/Users/kalpa/Documents/Mediscribe/electron/oauth-handler.js:133) accepts callback codes without state validation; the authorization request also lacks PKCE. It sends a success response before exchanging the code. If exchange fails, the catch attempts to set headers after the response ended, potentially leaving authentication unresolved. The listener uses a fixed port without a loopback-only host or explicit listen-error handling. Use state and PKCE, bind loopback, handle cancellation/port conflicts/timeouts, and send success only after verification. No real OAuth account was used to test this failure path.

### 12. P1: Logout does not clear Firebase authentication or UID

**Source confirmed.** [mediscribe-app.tsx:379](/Users/kalpa/Documents/Mediscribe/src/components/mediscribe-app.tsx:379) clears visible identity and Electron session state but does not call Firebase sign-out or clear `currentUserUid`. The previous provider session can survive visible logout. Clear provider auth, UID, entitlement state, and user-scoped subscriptions together; test logout and account switching with two accounts.

### 13. P2: Google session restore loses the canonical user key

**Source confirmed; account-shape dependent.** [mediscribe-app.tsx:110](/Users/kalpa/Documents/Mediscribe/src/components/mediscribe-app.tsx:110) restores email but not UID on the connected-Google branch, while entitlement lookup uses `currentUserUid || currentUser`. A subscription stored only under Firebase UID can therefore be missed after restart. Restore the provider identity first and consistently key entitlements by that verified identity.

### 14. P2: Forgot Password reports an email that was never sent

**Reproduced and UI observed.** [auth-page.tsx:258](/Users/kalpa/Documents/Mediscribe/src/components/auth-page.tsx:258) only shows a success toast; no password-reset provider call exists in that handler. Wire actual reset delivery and use a privacy-preserving confirmation only after the request is accepted; expose genuine transport failures.

### 15. P2: Browser Google login is simulated

**Source confirmed and UI observed.** [auth-page.tsx:238](/Users/kalpa/Documents/Mediscribe/src/components/auth-page.tsx:238) sets a timer and logs in a synthetic provider user on non-Electron platforms. The isolated UI reached pricing without Google authorization. This is not real authentication. Implement provider sign-in for web/Capacitor or explicitly mark that platform unsupported; keep demos outside production login.

### 16. P1: Failed cloud download can destroy the local copy

**Reproduced with an in-memory filesystem.** [google-drive-sync.js:85](/Users/kalpa/Documents/Mediscribe/electron/google-drive-sync.js:85) opens/truncates the destination before the remote request succeeds. It also resolves on source-stream end instead of completed destination writing. Download into a temporary file, validate the payload, await the full stream pipeline, then atomically replace the local copy. Preserve the original on all failures.

### 17. P2: Cloud sync suppresses transfer failures

**Reproduced.** [google-drive-sync.js:150](/Users/kalpa/Documents/Mediscribe/electron/google-drive-sync.js:150) ignores a false upload result; analogous download paths do the same. [main.js:227](/Users/kalpa/Documents/Mediscribe/electron/main.js:227) can consequently announce successful overall sync. Propagate structured failure/partial-success results and never mark unsent local changes as synchronized.

### 18. P2: Repeated template sync creates duplicate records

**Reproduced.** [google-drive-sync.js:198](/Users/kalpa/Documents/Mediscribe/electron/google-drive-sync.js:198) only treats keywords as keyed objects. Templates fall into a `Set` union that compares object identity, so two objects with the same template ID survive. Merge templates by stable ID with an explicit update/conflict/deletion policy.

### 19. P2: Template push/pull confirmation is never rendered

**Source confirmed.** [template-manager.tsx:203](/Users/kalpa/Documents/Mediscribe/src/components/template-manager.tsx:203) sets confirmation state and returns for push/pull. The component imports `SyncConfirmDialog` but never renders it. These actions therefore cannot proceed through the intended confirmation. Render the dialog and wire confirm/cancel, following the existing dictionary/keyword pattern.

### 20. P2: File templates sync local paths, not their attachments

**Source confirmed.** [main.js:237](/Users/kalpa/Documents/Mediscribe/electron/main.js:237) syncs template JSON; file templates retain a machine-local `filePath` that is opened at [main.js:2065](/Users/kalpa/Documents/Mediscribe/electron/main.js:2065). A second device will not acquire that attachment through this sync. Transfer attachments using stable remote identifiers, materialize local copies, and clearly report missing files.

### 21. P2: Deleting the active base model leaves an invalid selection

**Reproduced.** [main.js:6424](/Users/kalpa/Documents/Mediscribe/electron/main.js:6424) chooses `base.en` as fallback before deleting it. Deleting active `base.en` leaves it selected even when `tiny` exists. Exclude the deleted model from every fallback candidate and persist/restart only after a valid selection is established.

### 22. P2: Model-download listeners accumulate across mounts

**Reproduced.** [preload.js:48](/Users/kalpa/Documents/Mediscribe/electron/preload.js:48) registers wrapped event callbacks without returning cleanup; [model-selector.tsx:147](/Users/kalpa/Documents/Mediscribe/src/components/model-selector.tsx:147) cannot remove those listeners on unmount. Reopening the view adds handlers and can produce duplicate state updates/toasts. Return exact unsubscribe functions and invoke them in effect cleanup.

### 23. P2: Dictation reports successful insertion even when typing fails

**Source confirmed.** [dictation-view.tsx:283](/Users/kalpa/Documents/Mediscribe/src/components/dictation-view.tsx:283) ignores the native typing result and always reports success for nonempty transcription. The desktop path also does not preserve that text in the result UI. Check the result, retain recoverable transcript text, and provide copy/retry on failure. Separately, unsupported browser speech recognition currently substitutes a canned medical note (with a demo toast); production should report unsupported functionality instead.

### 24. P1: Installed build cannot be assumed to contain current tracking/admin fixes

**Package confirmed.** The inspected `/Applications/MediScribe.app/Contents/Resources/app.asar` lacks the newer first-open telemetry and Microsoft snapshot reader found in this working copy. It also lacks `firebase-admin`, which is a development dependency although privileged main-process admin/fallback paths require it. This explains an actual local release mismatch, not every Store customer's behavior. Move privileged reads to a backend, release a new version, and test its installed artifact. Merely editing source does not update existing installations.

### 25. P2: Source and country attribution are not reliable

**Source confirmed.** [tracker.ts:72](/Users/kalpa/Documents/Mediscribe/src/lib/tracker.ts:72) derives source from OS, so Store, direct-download and browser usage can share misleading desktop labels; it records no acquisition country. [admin-subscribers-service.ts:103](/Users/kalpa/Documents/Mediscribe/src/lib/admin-subscribers-service.ts:103) guesses country from currency/phone/email and defaults unknown to India. USD does not identify a US customer, and unknown is not India. Store acquisition geography, payment billing country, and estimated app geography must be separately labelled; record explicit distribution channel and retain Unknown when unavailable.

### 26. P2: Renderer and native telemetry can duplicate a first-open count

**Source confirmed; partial-failure dependent.** [tracker.ts:82](/Users/kalpa/Documents/Mediscribe/src/lib/tracker.ts:82) can successfully write first-open then fail the session write, triggering native fallback. [main.js:3339](/Users/kalpa/Documents/Mediscribe/electron/main.js:3339) uses a different first-install marker and random document ID. One installation can then produce two records. Share a stable installation/event ID across paths and perform idempotent ingestion with bounded retry. Browser-storage reset/reinstallation must also be documented as limitations of installation counts, not labelled unique people.

### 27. P2: Browser admin endpoint is absent from the static app

**Source/build confirmed.** [admin-subscribers-view.tsx:90](/Users/kalpa/Documents/Mediscribe/src/components/admin-subscribers-view.tsx:90) requests `/api/admin/subscribers` without Electron. The reviewed static-export app has no corresponding API route; the build emits the page and not-found route. Hosting could supply an external route, but none was verified. Deploy a real authenticated endpoint and configure it explicitly instead of relying on a route the export cannot serve.

### 28. P1: Dependencies need security triage and updates

**Registry audit result, not demonstrated exploits.** The lockfile audit reports 4 critical, 28 high, 16 moderate and 2 low affected package entries. Direct affected dependencies include Electron, Next, electron-builder, electron-updater, form-data, PostCSS, concurrently, firebase-admin and Resend. Some advisories apply to server/build features absent from the exported desktop runtime, so assess exposure individually. Upgrade supported compatible releases, regenerate the lockfile, rebuild native modules, and test signed installers; do not run an indiscriminate forced upgrade. See [dependency audit JSON](/Users/kalpa/Documents/Mediscribe/docs/audit/dependency-audit-2026-09-19.json).

### 29. P1: Supabase setup policy allows unrestricted row operations

**Conditional deployment risk; SQL confirmed.** [setup-supabase.sql:34](/Users/kalpa/Documents/Mediscribe/scripts/setup-supabase.sql:34) uses `FOR ALL`, `USING (true)`, and `WITH CHECK (true)` without an ownership predicate. For roles with table privileges this permits operations on other users' rows, not merely own-record upserts. Whether this script is deployed was not verified. Replace it with least-privilege policies or server-only ingestion; inspect actual grants/policies before enabling this path.

### 30. P2: Release builds do not enforce the checks that passed separately

**Source confirmed.** [next.config.js](/Users/kalpa/Documents/Mediscribe/next.config.js) permits build-time type/lint errors, and the inspected release workflows lack a complete regression gate. Passing a build is therefore insufficient. Make typecheck, lint, behavioral tests, secret scanning, dependency triage and installed-artifact smoke tests required before publication. Native bundling, signing, Store submission, Android release signing and updater installation were not executed in this audit.

## Download Counts and the Foreign-Download Question

The screenshot's user directory counts registered/paying profiles, not everyone who acquired or opened the app. Microsoft defines an acquisition as obtaining a license, and separately reports installs. Neither is an in-app registration. See [Microsoft acquisition report definitions](https://learn.microsoft.com/en-us/partner-center/insights/acquisitions-report).

The source/package findings establish several reasons your admin page can miss activity: old installed code, unavailable privileged fallback, no verified live ingestion/rules, weak source attribution, and no country measurement for anonymous opens. They do **not** prove that foreign downloads are fake, bots, or successful first launches. We did not obtain your actual Store country/time-range report or corresponding production events.

Keep Microsoft Partner Center sync. The sync script and mocked tests exist, but `PC_TENANT_ID`, `PC_CLIENT_ID`, `PC_CLIENT_SECRET`, and `PC_STORE_ID` were not configured in the inspected external configuration, so live synchronization is unverified. Run it on a protected backend/scheduled job, never with Partner Center secrets in the distributed app.

Your in-app admin dashboard should show separate measures: Store acquisitions, Store installs if collected, website/GitHub downloads, observed first opens, observed sessions, registered users, and paid accounts. Do not add these overlapping measures into a single unique-user total. Show source, reporting window/timezone, last successful sync, errors, and Unknown geography. First-open telemetry cannot reconstruct historical launches from old uninstrumented releases, and offline/blocked telemetry means it cannot count literally every opener.

## Recommended Repair Order

1. Contain distributed credentials, restrict admin/payment trust boundaries, and correct transcript-altering cleanup and data-loss sync.
2. Implement authenticated server-side orders, fulfillment, entitlement verification, admin reads and telemetry ingestion. Keep the dashboard inside your app.
3. Repair real authentication/reset/logout, durable payment recovery, cloud sync, model selection and native typing feedback.
4. Preserve separate Microsoft acquisitions and direct first-open metrics; add reliable attribution, idempotency, sync status and privacy controls.
5. Update dependencies with regression testing; publish a new signed version only after installed-artifact tests on each supported platform and a complete payment/activation test.

The current audit is a diagnosis and verification record, not a claim that the listed bugs are fixed.
